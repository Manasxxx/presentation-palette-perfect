## 0. Product Philosophy

### Visual-First, Always
- Each slide communicates **one idea**. If a slide has more than one primary message, it should be split or simplified.
- Text is support material. The visual — stat, image, animation, graphic — is the hero.
- If the slide can't be understood in 3 seconds of glancing, it needs redesigning.

### Message Hierarchy
- **H1-level:** The one thing you want them to remember. Big, bold, center/dominant.
- **H2-level:** One supporting detail or proof point. Smaller. Present only if needed.
- **Body-level:** Optional context. Never more than 2 sentences. Palanquin, muted color.
- **No paragraphs in slides.** Ever. Use fragments, stats, or single punchy lines.

### Lightweight as a Feature
- JS bundle target: under 800KB gzipped. Current: app chunk 165KB + vendors parallel-loaded ✓ (code-split via `vite.config.ts` manualChunks).
- Images: all deliverable assets must be WebP. PNGs allowed only as originals in `/src/assets` during dev. Run `npm run images:convert` (requires `npm i -D sharp`) to batch-convert to WebP.
- New or replacement client creatives from external folders such as Downloads must be converted to WebP before wiring them into the site; Session 47 added CTP creatives as `ctp-creative-4..12.webp`.
- Heavy effects (3D, particle systems, blur) are **gated on desktop only** via `useIsMobile()`. Never on mobile, except for foreground hero objects that have a deliberate mobile fallback/performance cap. **Documented exceptions (user-requested):** the Clients slide `PrismaticBurst` shimmer runs on mobile too (caps DPR at 1.25, pauses RAF offscreen), and the cover `Globe` runs on mobile (cobe is a light single-canvas renderer).
- Keep only the current slide plus immediate neighbors mounted. Placeholder sections preserve scroll height for the rest. This keeps the next/previous slide ready during native deck movement without keeping the whole deck's WebGL canvases, RAF loops, timers, or pointer listeners alive.
- Ambient WebGL backgrounds should cap device pixel ratio at `1.25` unless a specific foreground detail requires more. On Retina displays this is a major heat/lag control.
- Any future foreground WebGL hero object may use a higher desktop DPR only when the object carries brand detail. Keep mobile capped lower and document the exception in `context.md`.
- Any custom animation loop (`requestAnimationFrame`, interval, Anime.js timer/timeline, WebGL renderer) must pause or unmount when offscreen. Visibility gating is a product requirement, not a polish task.
- **Low-power mode lowers resolution, never removes (Session 45).** `useLowPowerMode()` (`src/hooks/use-low-power.tsx`) samples real rAF frame times ~5s after load; a median slower than ~35fps marks the machine low-power (sticky per browser session via `sessionStorage`). The three ambient shaders (Hyperspeed `maxPixelRatio`, LightRays `maxDpr`, PrismaticBurst `maxDpr`) then drop their DPR cap 1.25 → 0.75 — same visuals, ~64% fewer fragments. Owner rule: do NOT unmount or visually degrade effects for weak machines; lower their render resolution instead. New ambient effects must accept a DPR-cap prop and wire it to this hook.
- Lazy-load all case study images via Vite's `?url` + lazy `<img loading="lazy" />`.
- Code-split vendors: Anime.js, ambient 3D libraries, and UI libs — each in its own chunk (see `vite.config.ts`). GSAP was removed in Session 30; the orphaned lanyard 3D/physics stack and its `vendor-lanyard` chunk were fully removed in Session 32 (deps + asset + Lanyard component deleted). The largest chunk is now `vendor-3d` (`three` + `postprocessing` for Hyperspeed, desktop-gated; ~686 KB).

### Copy Discipline

- No agency-speak template on case studies. The pattern is **`Who they are. What we did.`** — never `Boosted / Drove / Amplified / Elevated [thing] through strategic [tactic]`. The seven case-study subtitles were rewritten to this pattern in Session 11. **Descriptions must be plain (not corporate) and outcome-based, and you must verify the client's real business before writing** — Session 32 found Baxsaa wrongly tagged "beauty commerce" when The Baxsaa Co is a Mumbai premium custom-packaging studio. When unsure of a client's identity, web-search first.
- Banned words across the deck: **strategic, amplified, elevated, boosted, drove, impactful, vibrant, compelling, powerful, Success** (as a heading suffix). These signal nothing and pattern-match to every other agency deck.
- Never rude — confidence without spite. Lines that knock other agencies or imply the client was broken before us are not on-brand.
- No em dashes. Use commas or periods. Mobile readability + matches the deck's terse rhythm.
- Service-card descriptions stay plainspoken, one sentence, never two clauses joined by "and that".
- Pillar labels use **B2B-buyer language**, not agency-internal jargon (e.g. "Demand Gen" not "Reach & Activation").

## 2. Code Principles

### Minimal State Management
- **Local React State:** There is deliberately no heavy global state management library (like Redux or Zustand). 
- **Prop Drilling for Core Interactions:** Features that require cross-component communication, like letting a specific slide trigger navigation (`onViewCaseStudies`), pass navigation handlers via props down to the slide component.
- **Navigation via Refs & Scrolling:** Slide transitions are managed natively by tracking the container scroll offset (`scrollTop / slideHeight`) inside `Index.tsx`, and explicit navigation triggers a `scrollTo` invocation on the `containerRef`. 

### Performance and Separation of Logic
- **Decoupled animations:** native scroll/snap owns travel; Anime.js owns local slide choreography. `SlideReveal.tsx` is only a lightweight IntersectionObserver wrapper. Never give a slide-local effect and the deck settle ownership of the same transform.
- **Mobile vs Desktop Branching:** `CaseStudyCarousel.tsx` branches on `useIsMobile()` into timed deterministic stacks: `.cs-mobile-stack` on phones and `.cs-desktop-stack` on desktop. There is no drag surface, Blossom, scroll-timeline carousel, or requestAnimationFrame tilt. Other computationally intensive effects (WebGL backdrops) remain gated behind `useIsMobile()` per the Lightweight rules above.
- **Active Slide Lifecycle:** `Index.tsx` should keep the current slide plus immediate neighbors mounted. This is the transition-smoothing window; anything farther away remains a placeholder so cumulative WebGL/RAF load stays bounded.
- **Slide-index math must use a measured slide height, never `window.innerHeight`.** `Index.tsx` derives the active slide from `scrollTop`, and the programmatic `scrollTo` multiplies by the per-slide stride. Use `getSlideHeight(container)` (measures a real `.slide` via `getBoundingClientRect`), not `window.innerHeight`: on mobile Chrome the URL bar auto-hides and `window.innerHeight` grows while the slides stay a constant height, so the index drifts low and compounds down the deck. Combined with a tight mount window, that drift can mount the wrong slide and show `SlideFallback` (the Session 28 real-phone black-screen bug). Do not reintroduce `window.innerHeight` into the slide-index or `scrollTo` math.
- **Animation Ownership:** If a component owns a RAF loop, WebGL renderer, interval, or pointer listener, it must clean it up on unmount and ideally pause it with IntersectionObserver when merely offscreen.
- **Contact logo centering:** the Contact mark uses a positioned wrapper plus an animated inner wrapper. Animate only `ct-mark-inner`; transforming `ct-mark` breaks centering. Desktop has no external halo. Mobile explicitly keeps the teal ripple halo.

## 3. Design and Aesthetic Principles

### Tailwind + Fixed Dark Theme
- **CSS Variable Injection:** Global styling overrides are defined fundamentally using CSS custom properties inside `@layer base` in `src/index.css`. This enforces a strict color token system (e.g. `--primary`, `--card`, `--owl-green`).
- **Fixed OwlSurf Dark Mode:** The deck no longer exposes a light/dark toggle. The dark OwlSurf presentation theme is the single production visual system.
- **Tailwind Utility Classes:** Components rely extensively on Tailwind classes for scaffolding, structure, layout (`flex`, `grid`, `absolute inset-0`), and standard spacing. 

### Fluidity and Animations
- **Anime.js for All Sequencing:** The project was migrated entirely away from Framer Motion. `Anime.js` now exclusively handles staggered entrance animations (resolving opacity, translation, scale) directly in components like `TitleSlide.tsx`, through shared slide-motion helpers, and through the deck-level transition layer.
- **Anime.js is the only animation library.** GSAP was removed in Session 30. `PillNav` (show/hide, hover circle-fill, mobile menu) and `CardSwap` (Services stack) are built on Anime.js (`animate`, `createTimeline`, `createTimer`, `utils`). Do not reintroduce GSAP.
- **CSS Transitions:** Standard hover effects and states explicitly specify easing parameters, ensuring fluid hover state inversions. Easing curves like `cubic-bezier(0.4, 0, 0.2, 1)` are used over harsh linear jumps.

### Aesthetic Patterns "The Glass and Glow"
- **Glassmorphism:** Navigation menus (`PillNav`), popovers, and specific slide cards rely on `backdrop-filter: blur() saturate()`. Elements are intended to sit fluidly over complex background arrays or 3D visuals.
- **Soft Emittance (Glow):** Gradients (`.text-gradient-green`, `.glow-green`) and box-shadow pulses give elements a neon, high-contrast, cyberpunk-adjacent glow against the otherwise dark backgrounds. Ensure any primary accent is accompanied by an underglow to give an illusion of light emissions.

## 4. Deployment Principles

### Local dev server

- Use `npm run dev:server` for local/Codex preview sessions. It keeps Vite on fixed port `8080`, clears stale listeners, writes logs/pid to ignored `.codex-runtime/`, and safely reuses a healthy server. Prefer this over raw background `npm run dev` in short-lived shell commands.

> The primary live site at https://www.owlsurf.com is push-to-deploy. https://www.owlsurf.media redirects to `.com`. Full mechanics and the recovery runbook live in `context.md` under "Deployment Pipeline & Operations".

- **A push to `main` is a deploy.** `.github/workflows/deploy.yml` POSTs `https://www.owlsurf.com/deploy` (token-gated), the VPS webhook (`deployment/server.js`) spawns `deployment/deploy.sh` detached, and that script does `git reset --hard origin/main` → `npm ci` → `npm run build` → `pm2 restart heyowlsurf`. The `.media` redirect is not the webhook target. Live in ~10-60s. Treat every push to `main` as a production release, not a checkpoint.
- **The Actions `200` is an ack, not a success.** The build runs detached after the response returns. A green Actions run means the webhook was received, not that the build passed. Confirm the live site visually after a push.
- **Deploy failures are silent.** No alerting. If a push doesn't appear live, check `gh run list`. A `curl: (28) ... Timeout` on port 443 is transient VPS unavailability (often build memory pressure from the `vendor-3d` Three.js chunk), not a repo bug. Retry flags for the webhook exist locally but are not pushed yet because workflow-file changes require `workflow` auth scope; for an already-failed run, recover with `gh run rerun <id>`. See the 2026-06-04 incident in `context.md`.
- **Never hand-edit files directly on the VPS.** `deploy.sh` runs `git reset --hard origin/main` on every deploy, which discards any uncommitted server-side edits. All changes go through `main`.
- **Do not commit secrets to the deploy path.** `DEPLOY_TOKEN` lives in GitHub Actions secrets and the VPS `.env` only. Standing security debt: the GitHub PAT currently in plaintext in `.git/config` must be rotated and the remote moved to SSH or a credential helper.
